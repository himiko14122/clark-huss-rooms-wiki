Clark Huss roomsにおける信号フレアは、スカッドが長いボイスチャットなしでも連携できるようにする標準化されたコミュニケーションマーカーです。ゲームには文字通りのフレアアイテムは含まれていませんが、この用語はベテランスカッドが距離を超えてコミュニケーションを取るために使う懐中電灯のパターン、音声キュー、コールアウト用語のシステムを指します。新規プレイヤーはボイスチャットに完全に依存しており、これは遅く、パニック状態になりがちです。ベテランは2秒以下で複雑な情報を伝えるために信号フレアを使用します。

このガイドでは、視覚信号として機能する懐中電灯のクリックパターン、音声信号として機能する標準化されたコールアウト、そしてスカッド全体の応答を引き起こす緊急プロトコルについて説明します。また、スカッド固有の信号フレアシステムを構築する方法と、信号が誤用されたときに発生する最も一般的な失敗についても学びます。

## 信号フレアとは

信号フレアは、長いボイスチャットの文章を置き換える事前合意されたコミュニケーションショートカットです。送信者と受信者の双方が意味を前もって知っているため、解釈時間が不要になることで機能します。

### **信号フレアのカテゴリー:**

| カテゴリー | 媒体 | 範囲 | 情報密度 |
|----------|--------|-------|---------------------|
| 懐中電灯パターン | 視覚 | 1〜2通路 | 低〜中 |
| 音声コールアウト | 音声 | サーバー全体 | 高 |
| アクション信号 | 動作 | 隣接通路 | 中 |
| バッテリー状態 | 暗黙的視覚 | サーバー全体 | 低 |

4つのカテゴリーが組み合わさって完全なコミュニケーションシステムを形成します。ほとんどのスカッドは4つすべてを組み合わせて使用します。

## 懐中電灯パターン信号

懐中電灯パターンは、事前合意された意味を伝えるクリックのシーケンスです。長いシーケンスはバッテリーと時間を浪費するため、パターンは短くなっています。

### **標準的な懐中電灯パターン:**

| パターン | 意味 |
|---------|---------|
| シングルクリック | 確認応答、「見ている」 |
| ダブルクリック | 注意、「停止して評価」 |
| トリプルクリック | Clark発見、「私の方向」 |
| ラピッドクリック(5回以上) | 緊急、「今すぐ助けが必要」 |
| 長押し | 安全な通路標識、「こっちに来て」 |
| オフにしてオン | チェックイン、「まだ生きてる?」 |

これらのパターンは、受信側のスカッドがボイスチャットなしで認識するため機能します。シングルクリックは普遍的に確認応答として理解されます。トリプルクリックは普遍的にClarkを意味します。

## 音声コールアウト信号

音声コールアウトは、音声が言語を運ぶため、最も情報密度の高い信号フレアです。課題は、追跡中にも十分に速くなるようにコールアウトを簡潔に保つことです。

### **標準的なコールアウト用語:**

| コールアウト | 意味 |
|---------|---------|
| 「Clark left」 | Clarkは発言者の左にいる |
| 「Clark right」 | Clarkは発言者の右にいる |
| 「Clark back」 | Clarkはスカッドの後方にいる |
| 「Clark front」 | Clarkはスカッドの前方にいる |
| 「Breathing close」 | 1通路以内でClarkの音声手がかり |
| 「Heartbeat distant」 | 2通路以上でClarkの音声手がかり |
| 「Chase」 | Clarkがアクティブに追跡中、フルスプリント |
| 「Clear」 | 監視エリアにClarkの音声手がかりなし |
| 「Dead end」 | 通路に出口なし |
| 「Door」 | 近くにロックされたドア |
| 「Junction」 | 判断点に接近中 |
| 「Battery」 | バッテリー状態の更新が必要 |
| 「Battery dead」 | 懐中電灯が切れた |
| 「Safe corridor」 | 前の通路が標識済み、安全に進入可能 |

用語は短く、事実に基づき、曖昧さのないものです。用語から逸脱すると混乱が生じます。

## アクション信号

アクション信号は、ボイスチャットなしでコミュニケーションを取る動作です。ボイスチャットが利用できない場合や、スカッドが無音でコミュニケーションを取る必要がある場合に便利です。

### **標準的なアクション信号:**

| 信号 | 動作 |
|--------|----------|
| スカッド停止 | リードが手を挙げるか、動きを止める |
| スカッド前進 | リードが歩きを再開する |
| スカッド隠蔽 | 全プレイヤーがしゃがむか、固まる |
| スカッド撤退 | 全プレイヤーが方向を反転する |
| ウェッジ形成 | プレイヤーがウェッジフォーメーションに移動 |
| バディアップ | プレイヤーが最も近いスカッドメイトとペアになる |
| ライトオフ | ライツマネージャーが懐中電灯をオフにする |
| ライトオン | ライツマネージャーが懐中電灯をオンにする |
| フォローミー | リードが移動し、スカッドが従う |
| ホールドポジション | リードが停止し、スカッドが停止する |

アクション信号は、スカッドが落ち着いた状態で練習しているときに最も効果的です。パニック状態では、スカッドが信号を忘れてボイスチャットに戻る可能性があります。

## 緊急プロトコル

緊急プロトコルは、特定のスカッド応答を引き起こす信号フレアです。状況が危機的であるため、通常の連携ルールをバイパスします。

**緊急プロトコルのトリガー:**

| トリガー | 信号 | スカッドの対応 |
|---------|--------|----------------|
| スカッドメイトダウン | 「Man down, [direction]」 | 最寄りのチームメイトが回収に向かい、他はカバーする |
| Clark追跡 | 「Chase, full sprint」 | 全プレイヤーがスプリント、懐中電灯なし、リードが脱出を誘導 |
| スカッドメイト迷子 | 「Separation, [direction]」 | スカッドが一時停止し、迷子のプレイヤーを呼びかける |
| バッテリー切れ | 「Battery dead, [player]」 | スカッドが音声のみモードに切り替え |
| 待ち伏せ | 「Ambush, [direction]」 | スカッドが即座に撤退、質問なし |
| 出口発見 | 「Exit, [direction]」 | スカッドが出口に集まり、リードが経路を確認する |

緊急プロトコルは、いつでも必要になる可能性があるため、暗記されています。スカッドはゲーム前のブリーフィングでこれらを練習します。

## バッテリー状態信号

バッテリー状態は、懐中電灯バーの視認性を通じて暗黙的に伝達されます。ライツマネージャーは、ボイスチャットなしでバッテリー状態を伝えるために特定の信号を使用します。

**バッテリー状態信号:**

| バッテリー状態 | 信号 |
|---------------|--------|
| 70%以上 | 通常のクリックパターン、表示不要 |
| 50〜70% | ライツマネージャーが毎分「battery half」をコール |
| 25〜50% | ライツマネージャーがシングルクリックのみに切り替え |
| 25%未満 | ライツマネージャーが「battery critical」をコール |
| 10%未満 | ライツマネージャーが「battery dying」をコール |
| 0% | 懐中電灯のクリックが認識されなくなる、音声のみ |

ライツマネージャーの責任は、バッテリー状態についてスカッドに情報を提供し続けることです。スカッドはこの情報を使用して懐中電灯の使用を計画します。

## スカッド信号システムの構築

すべてのスカッドは、プレイスタイルに合った信号システムを構築する必要があります。上記の標準信号は出発点ですが、スカッドはしばしばこれらをカスタマイズします。

**信号システムのカスタマイズオプション:**

1. サーバー内の一般的な状況に対するスカッド固有のコールアウトを追加する
2. スカッドが実行しやすい懐中電灯パターンを使用する
3. ゲームバージョンがプレイヤーカラーをサポートしている場合は、カラー役割を割り当てる
4. 特定のイベントのための特定のフレーズ(オーディオシグネチャ)を作成する
5. 今後の決定のための予防的信号を開発する

カスタマイズは文書化され、最初のランの前にリハーサルされるべきです。リハーサルなしでカスタマイズするスカッドは、プレッシャー下で信号を忘れます。

## プレッシャー下での信号規律

信号規律はプレッシャー下で崩れますが、それはスカッドが信号を最も必要とするときです。以下の規律ルールは崩壊を防ぎます。

**規律ルール:**

1. 信号のみ — 追跡中に即興のボイスチャットを使用しない
2. 一度に1つの信号 — 複数の同時信号は混乱を生む
3. 簡潔な実行 — 信号は2秒以内に完了する必要がある
4. 普遍的な用語 — 標準信号からの逸脱は許可されない
5. 落ち着いた実行 — 信号は落ち着いた声で伝えられる必要がある

スカッドメイトが信号規律から逸脱した場合、ライツマネージャーは事実に基づくコールアウトで彼らを軌道修正するべきです:「Use signals only.」

## 一般的な信号の失敗

これらの失敗は、スカッドが信号を誤用したときに一貫して現れます。それらを特定することで防止に役立ちます。

**失敗1: 即興のボイスチャット。** スカッドメイトが追跡中に標準的なコールアウトの代わりに完全な文章を使用します。文章に5秒かかり、スカッドは5秒の応答時間を失います。

**失敗2: 複数の同時信号。** 2人のスカッドメイトが同時に信号を出します。スカッドはどの信号が優先されるかを判断できず、応答が遅れます。

**失敗3: 一貫性のない用語。** スカッドメイトが同じ概念に対して異なる言葉を使用します(「chase」対「running」対「go go go」)。スカッドはどの言葉が正しいかを解釈する浪费时间をします。

**失敗4: プレッシャー下で忘れた信号。** スカッドメイトが追跡中に信号用語を忘れ、感情的な反応に戻ります。信号は暗記を必要とするため、失敗します。

**失敗5: 信号スパム。** スカッドメイトが懐中電灯をすばやくクリックしたり、コールアウトを繰り返したりして、Clarkの音声手がかりを隠すノイズを作り出します。信号規律は頻度について厳格です。

## 信号実行のトレーニング

信号実行は、パターンを迅速かつ正確に配信する必要があるため、練習が必要です。以下のトレーニングエクササイズは筋肉記憶を構築します。

**エクササイズ1: 懐中電灯パターンドリル。** 空のロビーで、各懐中電灯パターンを10回練習します。意識的な思考なしにパターンが実行されるように筋肉記憶を構築します。

**エクササイズ2: コールアウトスピードドリル。** 標準的な各コールアウトを配信するのにかかる時間を計ります。目標配信時間はコールアウト1つあたり1秒未満です。

**エクササイズ3: 信号認識ドリル。** スカッドメイトにランダムに信号を出してもらいます。1秒以内に信号を識別します。すべての標準信号で繰り返します。

**エクササイズ4: 追跡シミュレーション。** 通常のセッションを実行しますが、Clarkの音声手がかりが出現するたびに、スカッドが信号のみのコミュニケーションに切り替えます。これはプレッシャー下での信号使用を構築します。

**エクササイズ5: 緊急プロトコルドリル。** 各セッションで少なくとも1回、各緊急プロトコルを練習します。暗記には反復が必要です。

## ソロプレイでの信号フレア

ソロプレイはスカッド信号の恩恵を受けませんが、ソロプレイヤーは規律を維持するために自己信号を使用できます。自己信号は、プレイヤーが自己規制のために単独で実行するパターンです。

**ソロ自己信号:**

| 信号 | 自己規制の使用 |
|--------|---------------------|
| 各分岐でのシングルクリック | 懐中電灯規律を維持する |
| フットステップカウント | 制御されたペースを維持する |
| 各ターンでのスタミナチェック | リソースの意識を維持する |
| 毎分のバッテリーチェック | バッテリー管理を維持する |

ソロプレイヤーは、スカッドの説明責任がなくても規律を強制するため、これらの信号の恩恵を受けます。

## よくある質問

**信号フレアはランダムなパブリックプレイヤーと機能しますか?**

めったにありません。ランダムなプレイヤーはあなたのスカッドの信号システムを知りません。信号フレアは、ボキャブラリーをリハーサルしてきた一貫したスカッドメイトと最もよく機能します。

**標準的な信号用語をカスタマイズすべきですか?**

はい、ただしスカッドが標準用語を習得した後にのみです。カスタマイズは複雑さを加え、標準用語はほとんどの状況で十分です。

**スカッドはいくつの信号を暗記すべきですか?**

標準用語には約15の信号があります。スカッド固有の信号を5〜10個追加すると、合計は20〜25信号になります。それを超えると、プレッシャー下で記憶するにはシステムが複雑すぎます。

**最も重要な信号は何ですか?**

「Chase」信号は、最も重要なスカッド応答を引き起こすため、最も重要です。リアガードがコールした瞬間、すべてのスカッドメンバーが即座に実行する必要があります。

**信号フレアはボイスチャットを完全に置き換えることができますか?**

十分にリハーサルされたスカッドでは、はい。信号システムはすべての一般的なシナリオをカバーします。ボイスチャットは、信号が対応できない異常な状況のために予約されています。

信号を実行するスカッドの役割の詳細については、[co-op survival guide](/en/multiplayer/co-op-survival-guide/)をご覧ください。信号フレアが実現する脱出戦術を学ぶには、[escaping Clark](/en/guides/escaping-clark/)を読んでください。


**ツールや発見をコミュニティと共有するにはどうすればよいですか?**

コミュニティWikiとDiscordが、ツールを共有する主要なチャンネルです。Wikiへの貢献は編集基準に従いますが、Discordはより少ない構造で非公式な共有を可能にします。最も成功したツールは、利用可能なリソースのギャップを特定し、コミュニティと協力してアプローチを改良する個々の貢献者から生まれています。便利なツールを作成した場合は、入力/出力仕様と使用例で明確に文書化してください。これにより、他の人が混乱なく採用できます。

**依存しているツールが機能しなくなった場合はどうすればよいですか?**

ツールの文書化されたフィードバックチャネルを通じて、即座に問題を報告してください。Wikiベースのツールの場合は、ディスカッションページを使用してください。Discordで共有されているツールの場合は、作成者に直接連絡してください。ほとんどのコミュニティツールメンテナーはバグレポートに迅速に対応し、事前の通知に感謝します。修正を待つ間、代替ツールや手動の方法に切り替えてください。回避策を文書化することで、他の影響を受けるユーザーが一時的な解決策の恩恵を受けることができます。

**サードパーティのツールをアカウント情報で信用できますか?**

アカウント情報をツールと決して共有しないでください。正規のツールはゲームの公開インターフェースを介して動作し、ログインを必要としません。ツールがRobloxパスワードを要求する場合、それは主張された目的に関係なく正規のものではありません。統計追跡などのパーソナライズされた機能の場合、ツールは(公開されている)ゲーム内のユーザー名のみを要求し、パスワードは要求しません。

**新しいツールを学ぶのにどのくらい時間がかかりますか?**

ほとんどのコミュニティツールには、数分で基本的な使用を可能にする直感的なインターフェースがあります。習熟には通常、ツールの複雑さに応じて、1〜2週間の定期的な使用が必要です。トレーニング方法論に複数の段階があるため、オーディオアナライザーはより多くの時間を必要とします。バッテリー計算機やパッチトラッカーはよりシンプルで学習が容易です。コミュニティDiscordチャンネルには、しばしば新しいユーザーが学習曲線を進めるのを手伝う意欲のあるベテランユーザーがいます。

**複数のツールを同時に使用すべきですか?**

はい、補完的なツールは互いに強化されます。たとえば、バッテリー計算機と一緒にオーディオアナライザーを使用すると、オーディオスキル開発とリソース管理計画の両方を提供します。重要なのは、ツールが互いに競合しないか、情報の過多で圧倒されないようにすることです。1〜2つの必須ツールから始めて、快適になったらさらに追加してください。

**ツールが高品質かどうかをどうやって知ることができますか?**

品質の指標には、積極的なメンテナンス、コミュニティディスカッション、明確なドキュメント、定期的な更新、ベテランの肯定的な endorsement が含まれます。数ヶ月更新されていないツールは放棄されている可能性があります。アクティブなDiscordチャンネルと迅速に対応するメンテナーがいるツールは、より信頼性が高い傾向があります。コミュニティの評判は強力な品質指標です。
