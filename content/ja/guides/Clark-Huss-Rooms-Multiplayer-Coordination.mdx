マルチプレイヤー連携は、Clark Huss roomsをソロのホラー体験からチームサバイバルチャレンジへと変えますが、それはスクワッドが実際に連携する場合に限ります。ランダムな公開ロビーはめったに効果的にコミュニケーションできないため、サバイバル率は連携の質によって劇的に変化します。強力なコールアウトと明確な役割を持つ連携のとれた3人組は、同じ空間にいるソロプレイヤーのフルロビーと比べて、生存時間が2倍になります。

このガイドでは、3つのコアなスクワッド役割（リード、後衛、ライトマネージャー）、コミュニケーションを高速化するコールアウト用語、そして混沌を防ぐボイスチャットの規律について説明します。また、チェイス中にフォーメーションを維持するスクワッドの移動パターンと、単一プレイヤーの燃え尽きを防ぐ役割ローテーションシステムについても学びます。

## 3つのコアなスクワッド役割

連携のとれたすべてのスクワッドは、サーバーロックが作動する前に3つの役割を割り当てます。これらの役割は、ナビゲーション、脅威検知、フラッシュライト管理の認知負荷を分散し、単一のプレイヤーがすべての責任を負うことを防ぎます。

### **役割の責任：**

| 役割 | 主な機能 | 副次的な機能 | 重要なスキル |
|------|------------------|---------------------|-----------|
| リード | ナビゲーションと経路選択 | 通路タイプの認識 | 空間記憶力 |
| 後衛 | Clarkの音声監視 | スクワッドの分離防止 | 音声的手がかりの解釈 |
| ライトマネージャー | フラッシュライトのタイミングとバッテリー | スクワッドの視覚的確認 | クリックの規律 |

リードは前を歩き、各分岐点でどちらの通路に入るかを選択します。後衛は最後に歩き、Clarkの音声的手がかりを聞き取り、方向と距離をコールアウトします。ライトマネージャーは中間に歩き、フラッシュライトのクリックでスクワッドが視覚的確認を持つタイミングを制御します。

デュオ（2人）では、リードとライトマネージャーを1つの役割に統合します。クアトロ（4人）では、ライトマネージャーを「クリッカー」と「スキャナー」のサブ役割に分割します。フルロビーでは、3つの役割を複数のプレイヤーに複製し、指定された主要保有者を配置します。

## リード役割の詳細

リードの主な機能はナビゲーションであり、つまり通路レイアウトのスクワッドのメンタルマップを構築する必要があります。すべての分岐点の決定を行い、間違ったターンの結果責任を負います。

### **リードの責任：**

- すべてのT字路でどちらの分岐を取るかを選択する
- スクワッドが突入する前に行き止まりパターンを認識する
- 通過した通路のメンタルカウントを維持する
- 次の決定ポイントをスクワッドに伝える
- 音声監視ウィンドウに基づいて歩行ペースを設定する

### **リードの決定フレームワーク：**

| 分岐タイプ | 決定基準 |
|---------------|-------------------|
| T字路（2つの分岐） | エコーが強い（より長い通路）分岐を選択する |
| 1つのドアがある広い部屋 | 入ってスキャンし、2番目の出口があれば記録する |
| 長くまっすぐな通路 | 前進し、Escape経路を設定する |
| 行き止まりの認識 | 即座に引き返し、スクワッドに伝える |

リードは、スクワッド内で最も空間記憶力が強いプレイヤーであるべきです。誰も空間記憶力が強くない場合は、リードの役割を最も忍耐強いプレイヤーに割り当ててください。リードの決定は時間とともに蓄積され、性急な決定はスクワッドにコストがかかるからです。

## 後衛役割の詳細

後衛の主な機能はClarkの音声監視であり、つまり常に後ろを向いているか、最低限後ろを聞いています。彼らはスクワッドの早期警戒システムです。

### **後衛の責任：**

- スクワッドの後ろからの音声的手がかりを監視する
- 15秒ごとにClarkの位置更新をコールアウトする
- 呼吸リズムと心拍の方向を特定する
- 歩行から制御された後退に切り替えるタイミングをスクワッドに警告する
- スクワッドの分離距離を監視する（誰か遅れたらコールアウトする）

**後衛のコールアウト形式：**

| 音声的手がかり | コールアウト形式 |
|------------|----------------|
| 心拍 | 「心拍、2通路後方」 |
| 呼吸 | 「呼吸、1通路後方、方向[左/右]」 |
| 足音 | 「足音、隣接する部屋」 |
| ささやきの断片 | 「ささやき、同じ通路」 |
| 突進バースト | 「Clarkチェイス、今すぐ全力疾走」 |

後衛は、最も音声解釈スキルが高いプレイヤーであるべきです。チェイス中も冷静を保つ必要があります。彼らのコールアウトがスクワッドの対応を決定するからです。

## ライトマネージャー役割の詳細

ライトマネージャーは、スクワッド全体のフラッシュライトのタイミングを制御します。彼らのクリックは、スクワッドに短い視覚的ウィンドウを提供するようにタイミングされており、その後、全員が音声監視ウィンドウ中に暗闇の中で移動します。

**ライトマネージャーの責任：**

- 決定点でのみフラッシュライトをクリックする
- クリックを0.3〜0.5秒ちょうどに持続するようにタイミングする
- 分岐点のアプローチタイミングについてリードと調整する
- 1分ごとにバッテリー状態をスクワッドに伝える
- バッテリーが50％を下回ったらクリックのみモードに切り替える

**ライトマネージャーのクリックタイミングプロトコル：**

| 状況 | クリックパターン |
|-----------|---------------|
| スクワッドが分岐点に接近中 | 分岐点の5メートル前で1回クリック |
| スクワッドが新しい通路に入る | 通路入口で1回クリック、その後暗闇の中を歩く |
| Clarkの音声的手がかりを検知 | クリックなし、音声監視のみ |
| スクワッドが広い部屋に到達 | 左、中央、右をカバーする3回のクリック |
| スクワッドが安全な通路に近い | クリックなし、バッテリーを節約 |

ライトマネージャーは、最もフラッシュライトの規律が強いプレイヤーであるべきです。彼らはスクワッドのバッテリー管理者であり、彼らのクリックがスクワッドが視覚的カバレッジを維持できる期間を決定します。

## コールアウト用語

標準化されたコールアウトはコミュニケーションを高速化します。なぜなら、話し手と聞き手の両方がコールアウトの意味を正確に知っているからです。用語から逸脱すると混乱が生じます。

**標準コールアウト用語：**

| コールアウト | 意味 | 緊急度 |
|---------|---------|---------|
| 「クリア」 | エリアは安全、Clarkの音声的手がかりなし | 低 |
| 「ハートビート」 | 遠距離のClarkの音声、現在ペース継続 | 中 |
| 「ブレathing」 | 近距離のClark、一時停止して評価 | 高 |
| 「チェイス」 | Clarkがアクティブに追跡中、全力疾走 | 緊急 |
| 「行き止まり」 | 通路に出口なし、引き返す | 中 |
| 「ジャンクション」 | 決定点に接近中 | 低 |
| 「広い部屋」 | 広い空間に入る、スキャンが必要 | 中 |
| 「バッテリークリティカル」 | ライトマネージャー15％以下、音声のみに切り替え | 高 |
| 「バッテリー切れ」 | フラッシュライト消耗、音声のみナビゲーション | 緊急 |
| 「ドアロック」 | ドアインジケーターがロック表示、試行しない | 低 |

用語が短いのは、高圧的な瞬間にボイスチャットが高速でなければならないからです。長い文章はスクワッドの応答時間を遅らせます。

## ボイスチャットの規律

ボイスチャットの規律は、連携のとれたスクワッドと混沌としたスクワッドを区別します。規律は制限的ですが効果的です。

**ボイスチャットルール：**

1. プッシュ・トゥ・トークのみ — オープンマイクはClarkの音声的手がかりを隠す背景ノイズを作成する
2. 事実のみ — 感情は意思決定を遅くする
3. 一度に1人の話者 — 重複する音声はClarkの音声よりも解釈が難しい
4. 簡潔なコールアウト — コールアウトごとに3秒未満
5. 落ち着いた声のトーン — チェイス中でも測定されたペース

**ボイスチャット音量ミックス：**

| 音声ソース | 推奨音量 |
|--------------|--------------------|
| ゲーム環境 | 70% |
| Clarkの音声的手がかり | 75% |
| スクワッドボイスチャット | 40% |
| 音楽/SFX | 0% |

Clarkの音声レイヤーを環境ベースライン以上にブーストすることで、スクワッドがコミュニケーション中でもClarkの音声的手がかりが聞き取れる状態を確保します。

## スクワッドの移動パターン

移動パターンは、探索とチェイス中にスクワッドの結束力を維持します。以下のパターンは連携プレイで実証済みです。

**ウェッジフォーメーション：** スクワッドはウェッジ形状で移動し、リードが前、ライトマネージャーが中央、後衛が後ろに配置されます。このフォーメーションは、役割の分離を維持しながら全員が視覚範囲内にいることを保ちます。

**一列縦隊：** スクワッドは一列で移動し、リードがナビゲートし、ライトマネージャーがリードの後ろ、後衛が後ろに配置されます。複数の足音からの音声ノイズを減らすため、音声監視が重要な場合に使用されます。

**バディシステム：** 各プレイヤーは1人のスクワッドメイトとペアになります。ペアは一緒に移動し、視覚的接触を維持します。混沌としたロビーで使用されます。スクワッドが分裂しても孤立を防ぐためです。

**スターフォーメーション：** リードが中心にあり、他の3人のプレイヤーが基点方向に放射状に広がります。Clarkがどの方向からも接近できる広い部屋で使用されます。リードが中心的な決定を行い、他のプレイヤーは自分の象限を監視します。

**ローテーションパターン：** リードと後衛は2分ごとに交代します。これにより、持続的な役割責任からの疲労を防ぎ、すべてのスクワッドメンバーをナビゲーションと音声監視の両方のスキルに慣れさせます。

## サーバーロックの同期化

サーバーロックには同期化されたアクションが必要です。同期化がないと、1人のプレイヤーが準備ができていないうちにロックを早期に作動させてしまいます。

**5秒同期シーケンス：**

1. 5秒前：ライトマネージャーがバッテリー状態を確認
2. 4秒前：リードがナビゲーション経路を確認
3. 3秒前：全員がフラッシュライトをクリックして機能を確認
4. 2秒前：リードが「3、2、1で開ける」とコール
5. 1秒前：リードがドアを開け、スクワッドが一緒に移動

このシーケンスは、最も一般的な同期化の失敗、つまりプレイヤーを孤立させるソロの急いでいる通過を防ぎます。

## チェイスプロトコル

Clarkのチェイス中、スクワッドはユニットとして応答する必要があります。個別の応答は孤立と死につながります。

**チェイス対応プロトコル：**

1. 後衛は、Clarkの音声的手がかりがアクティブな追跡を示す瞬間に「チェイス」とコールする
2. スクワッドは全力疾走に切り替え、フラッシュライトをオフにする
3. リードは2つのコーナーブレークがあるEscape経路を選択する
4. スクワッドはユニットとして移動し、視覚的接触を維持する
5. 後衛はClarkの追跡解除を監視する
6. 追跡解除後、スクワッドは制御された後退ペースに切り替える

**チェイスフォーメーション：** アクティブなチェイス中、ウェッジフォーメーションが最も効果的です。後衛がClarkの追跡方向を監視し、リードがEscape経路をナビゲートできるためです。

## 役割ローテーションシステム

固定された役割割り当ては、時間の経過とともに疲労とスキルの不均衡を引き起こします。ローテーションシステムは、すべてのスクワッドメンバー間で役割責任を分散します。

**スクワッドサイズ別のローテーションタイミング：**

| スクワッドサイズ | ローテーション間隔 |
|------------|-------------------|
| デュオ | 5分 |
| トリオ | 4分 |
| クアトロ | 3分 |
| フルロビー | 2分 |

ローテーション中、現在のリードが後衛になり、後衛がライトマネージャーになり、ライトマネージャーがリードになります。各プレイヤーはすでに移動先の役割で訓練されているため、ローテーションはスムーズです。

## ランブリーフィング前

連携のとれたすべてのスクワッドは、サーバーロック前に30秒のブリーフィングを行います。ブリーフィングは役割を確立し、コールアウトを確認し、計画をレビューします。

**ランブリーフィング前チェックリスト：**

1. すべてのスクワッドメンバーが参加していることを確認する
2. リード、後衛、ライトマネージャーの役割を割り当てる
3. 計画された最初のドアのタイミングを述べる
4. ボイスチャットのプッシュ・トゥ・トークがアクティブであることを確認する
5. 該当する場合は落ち着いた声の指定を確認する
6. スクワッド固有のルール（無線沈黙ウィンドウなど）を述べる

ブリーフィングは30秒かかり、最も一般的な連携の失敗を防ぎます。

## 一般的な連携の失敗

これらの失敗は、連携のとれていないスクワッドで一貫して現れます。それらを特定することで、自分のスクワッドでそれらを防ぐのに役立ちます。

**失敗1：複数のリード。** 2人以上のプレイヤーが同時にナビゲートしようとし、スクワッドが矛盾した指示に従います。解決策：ランが始まる前にリード役割を割り当てます。

**失敗2：無音の後衛。** 後衛がClarkの音声的手がかりをコールアウトせず、スクワッドはチェイスの前に警告を受けません。解決策：15秒更新ルールを強制します。

**失敗3：フラッシュライトスパム。** 複数のプレイヤーがランダムにフラッシュライトをクリックし、重複する露出を作成します。解決策：ライトマネージャーがすべてのフラッシュライトクリックを制御します。

**失敗4：パニックボイスチャット。** 感情的な反応が事実のコールアウトを置き換え、スクワッドが共有パニックに陥ります。解決策：落ち着いた声の指定。

**失敗5：早期ドア開放。** 1人のプレイヤーがスクワッドが同期される前に最初のドアを開けます。解決策：5秒カウントダウンプロトコル。

## よくある質問

**連携を効果的に行うのに3人のプレイヤーが必要ですか？**

いいえ。デュオでも割り当てられた役割の恩恵を受けます。最小連携要件は1人のリードと1人の後衛です。デュオプレイではライトマネージャーをリードと組み合わせることができます。

**ランダムな公開プレイヤーと連携できますか？**

めったにありません。公開ロビーの連携には、ゲーム前の明示的な合意が必要ですが、ほとんどのランダムプレイヤーはそれに関与しません。信頼できる連携のために友達とプレイしてください。

**最も重要な役割は何ですか？**

後衛が最も重要です。なぜなら、彼らのコールアウトがサプライズチェイスを防ぐからです。ナビゲーションが中途半端な優れた後衛は、音声監視が悪い素晴らしいリードを上回ります。

**テキストチャットとボイスチャットのどちらを使用すべきですか？**

チェイス中はテキスト入力が遅すぎるため、ボイスチャットが強く推奨されます。テキストチャットはゲーム前のブリーフィングには機能しますが、リアルタイム連携では失敗します。

**連携を拒否するスクワッドメイト怎么处理しますか？**

1人のプレイヤーが役割システムに関与しない場合は、その責任を自分の役割に引き受けてください。スクワッドが分裂するのを許すよりも、1人のプレイヤーが複数の役割をカバーする方が良いでしょう。

特定の役割メカニクスの詳細については、[協力サバイバルガイド](/en/multiplayer/co-op-survival-guide/)をご覧ください。スクワッド連携を必要とするEscape戦術を学ぶには、[ClarkからのEscape](/en/guides/escaping-clark/)を読んでください。


**自分のツールや発見をコミュニティと共有するにはどうすればよいですか？**

コミュニティWikiとDiscordがツールを共有する主要なチャンネルです。Wikiの貢献は編集基準に従いますが、Discordではより少ない構造で非公式な共有が可能です。ほとんどの成功したツールは、利用可能なリソースのギャップを特定し、その後コミュニティと協力してアプローチを洗練する個々の貢献者から生まれます。便利なツールを作成した場合は、入力/出力仕様と使用例で明確に文書化してください。これにより、他の人が混乱なく採用できます。

**依存しているツールが動作を停止した場合はどうすればよいですか？**

ツールの文書化されたフィードバックチャネルを通じて、すぐに問題を報告してください。Wikiベースのツールの場合は、ディスカッションページを使用してください。Discordで共有されているツールの場合は、作成者に直接連絡してください。ほとんどのコミュニティツールメンテナーは、バグレポートに迅速に対応し、事前の通知に感謝しています。修正を待っている間は、別のツールや手動の方法に切り替えてください。一時的な解決策を文書化して、他の影響を受けるユーザーがあなたの一時的な解決策の恩恵を受けられるようにしてください。

**アカウント情報を第三者ツールに信頼してもよいですか？**

アカウント資格情報をツールと共有しないでください。正当なツールはゲームの公開インターフェースを介して動作し、ログインを必要としません。ツールがRobloxパスワードを求める場合、それは主張された目的に関係なく正当ではありません。統計追跡などのパーソナライズされた機能の場合、ツールはパスワードではなく（公開されている）ゲーム内ユーザー名のみを要求するはずです。

**新しいツールを学ぶのにどのくらい時間がかかりますか？**

ほとんどのコミュニティツールは、数分以内に基本的な使用を可能にする直感的なインターフェースを持っています。習熟には通常、ツールの複雑さに応じて、定期的な使用で1〜2週間かかります。オーディオアナライザーは、トレーニング方法に複数の段階があるため、より時間が必要です。バッテリー計算機とパッチトラッカーはシンプルで学びやすいです。コミュニティDiscordチャンネルには、新参者が学習曲線を乗り越えるのを手伝う意欲のあるベテランユーザーがいることがよくあります。

**複数のツールを同時に使用すべきですか？**

はい、補完的なツールは互いに強化します。たとえば、オーディオアナライザーをバッテリー計算機と一緒に使用すると、オーディオスキル開発とリソース管理計画の両方が得られます。重要なのは、ツールが互いに競合したり、情報の過負荷を引き起こしたりしないことを確認することです。1つまたは2つの必須ツールから始めて、快適になったらさらに追加してください。

**ツールが高品質かどうかをどうやって知ることができますか？**

品質指標には、アクティブなメンテナンス、コミュニティディスカッション、明確なドキュメント、定期的な更新、ベテランの肯定的な推薦が含まれます。数ヶ月更新されていないツールは放棄されている可能性があります。アクティブなDiscordチャンネルと迅速に対応するメンテナーがいるツールは、より信頼性が高い傾向があります。コミュニティの評判は強力な品質指標です。
