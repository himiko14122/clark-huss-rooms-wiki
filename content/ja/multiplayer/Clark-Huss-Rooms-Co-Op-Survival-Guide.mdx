Clarkハスルームでのco-opサバイバルには、ソロプレイでは必要とされない連携が求められます。サーバーロック機能により、すべてのsquadメンバーが最初の扉からコミットしていることが保証され、音声優先設計により効果的なコミュニケーションをとるsquadが報われます。連携のとれたsquadは、同じサーバー内の連携のないプレイヤーよりも一貫して2〜3倍長く生存します。

このガイドでは、squadの役割分担、コールアウトシステム、フォーメーション戦略、Clarkの協調回避など、co-opサバイバルの基本を解説します。また、squadの失敗、コミュニケーションの崩壊、チーム全体での対応が必要な緊急事態の対処法についても学びます。

## Co-opが重要な理由

Co-opプレイはClarkハスルームの体験を大きく変えます。ソロプレイとの違い simply having more players を超えたものです。

### **Co-opの利点：**

| 利点 | 説明 |
|---------|-------------|
| 生存時間の延長 | 連携されたランはより長く続く |
| 個人への圧力の軽減 | 役割が責任を分散する |
| 音声モニタリングの共有 | 複数のリスナーがより多くをカバー |
| フラッシュライトバッテリーのローテーション | 節約が可能 |
| フォーメーションによる脱出オプション | 協調撤退 |
| 社会的エンゲージメント | 共有体験 |

連携度が高いほど、利点は複合的に積み上がります。トップsquadは、ソロプレイヤーでは到達できない生存時間を達成します。

## 3つのコア役割

すべての連携squadは、サーバーロック前に3つの役割を割り当てます。この役割により、ナビゲーション、脅威検出、フラッシュライト管理の認知的負荷が分散されます。

### **役割の定義：**

| 役割 | 機能 | 主なスキル |
|------|----------|-----------|
| リード | ナビゲーションと経路選択 | 空間記憶 |
| リアガード | Clarkの音声モニタリング | 音声の解釈 |
| ライトマネージャー | フラッシュライトのタイミング | クリックの規律 |

デュオでは、リードとライトマネージャーが統合されます。クアトロでは、ライトマネージャーがスキャナーとクリッカーのサブ役割に分割できます。フルロビーでは、複数のプレイヤーが各役割を共有できます。

## ゲーム前のブリーフィング

ゲーム前のブリーフィングは、サーバーロック前に役割と計画を決定します。ブリーフィングは30秒で完了しますが、ほとんどの連携失敗を防ぎます。

### **ブリーフィングチェックリスト：**

| ステップ | 所要時間 |
|------|----------|
| 全プレイヤーの参加確認 | 5秒 |
| 役割の割り当て | 10秒 |
| 最初の扉のタイミング計画を表明 | 5秒 |
| プッシュトゥトークが有効か確認 | 5秒 |
| 冷静な声の指定を承認 | 5秒 |

ブリーフィングが簡潔なのは、ゲーム前の長すぎる議論は多くの場合、明確にするよりも混乱を招くためです。重要な点に絞ってください。

## 標準コールアウト用語

標準化されたコールアウトにより、解釈のオーバーヘッドなしにsquadが迅速にコミュニケーションできます。用語は短く、曖昧さはありません。

### **コールアウトリファレンス：**

| コールアウト | 意味 |
|---------|---------|
| "Clark left" | Clarkは発言者の左にいる |
| "Clark right" | Clarkは発言者の右にいる |
| "Clark back" | Clarkはsquadの後方にいる |
| "Clark front" | Clarkはsquadの前方にいる |
| "Breathing close" | Clarkの音声テルが1つの廊下以内にある |
| "Chase" | Clarkがアクティブに追跡中 |
| "Clear" | 監視エリアにClarkの音声テルなし |
| "Dead end" | 出口がない、引き返す |
| "Door" | 近くにロックされたドアがある |
| "Junction" | 前方に分岐点がある |
| "Battery half" | ライトマネージャーのバッテリーが50% |
| "Battery critical" | ライトマネージャーのバッテリーが15%未満 |

この用語はコミュニティ全体で共有されているため、どの連携squadともコミュニケーションできます。

## ウェッジフォーメーション

ウェッジフォーメーションは、デフォルトのco-opフォーメーションです。音声モニタリングを分散しながら、視覚的接触を維持します。

**ウェッジフォーメーション：**

| 位置 | 役割 | 機能 |
|----------|------|----------|
| 前方 | リード | ナビゲーションとルート決定 |
| 中央 | ライトマネージャー | フラッシュライトのタイミング制御 |
| 後方 | リアガード | Clarkのモニタリング |

フォーメーションはsquadの動きに基づいて、時計回りまたは反時計回りに回転できます。回転により役割の疲労を防ぎます。

## シングルファイルフォーメーション

シングルファイルフォーメーションは、狭い廊下や音声モニタリングが重要な場合に使用されます。このフォーメーションは、複数の足音からの音声ノイズを削減します。

**シングルファイルフォーメーション：**

| 位置 | 役割 | 機能 |
|----------|------|----------|
| 前方 | リード | ナビゲーション |
| 2番目 | ライトマネージャー | フラッシュライト制御 |
| 3番目 | リアガード | 音声モニタリング |

シングルファイルフォーメーションは、プレイヤーが視覚的接触を失う可能性があるため、チェイス中は維持するのが難しくなります。

## バディシステム

バディシステムは、各プレイヤーを1人のsquadメイトとペアにします。このシステムは、Clarkの主要なターゲットメカニズムである孤立を防ぎます。

**バディシステムルール：**

| ルール | 説明 |
|------|-------------|
| 各プレイヤーに1人のバディがいる | ペアの割り当てはラン中固定 |
| バディは視界範囲内に留まる | 最大5メートル離れる |
| バディはお互いの音声をカバーする | 各ペアが2方向をモニタリング |
| 片方のバディが死亡した場合、生存者は別のペアに合流する | Squadが再編成される |

バディシステムは単純ですが、孤立による死亡を防ぐのに効果的です。

## ボイスチャットの規律

ボイスチャットの規律は、Clarkの音声テルを圧倒する音声のカオスを防ぎます。この規律は制限的ですが、必要です。

**ボイスチャットルール：**

| ルール | 目的 |
|------|---------|
| プッシュトゥトークのみ | 背景雑音を防止 |
| 事実に基づく内容 | 感情的な反応を避ける |
| 一度に1人の発言者 | 重複を防止 |
| 簡潔なコールアウト | コールアウトは1回3秒未満 |
| 冷静な声 | チェイス中は落ち着いたペース |

これらのルール違反は、squadの連携効率を大幅に低下させます。

## 緊急プロトコル

緊急プロトコルは、特定のsquad全体の対応を起動します。状況が重要であるため、通常の連携ルールをバイパスします。

**緊急プロトコル：**

| トリガー | シグナル | 対応 |
|---------|--------|----------|
| マン down | "Man down, [方向]" | 最寄りのチームメイトが回復し、他のメンバーがカバーする |
| フルチェイス | "Chase, sprint now" | 全プレイヤーがスプリント、フラッシュライトOFF |
| 分離 | "Separation, [方向]" | Squadが一時停止し、分離したプレイヤーに声をかける |
| バッテリー切れ | "Battery dead, [プレイヤー名]" | Squadが音声のみモードに切り替え |
| 待ち伏せ | "Ambush, [方向]" | 即時撤退、質問なし |
| 出口発見 | "Exit, [方向]" | Squadが出口に収束する |

これらのプロトコルは、最初のラン前に暗記されます。プレッシャー下で自動的に実行されます。

## ライトマネージャーのローテーション

ライトマネージャー役割は、squadのフラッシュライトのタイミングを制御します。プレイヤー間のローテーションにより、バッテリーコストが分散されます。

**squadサイズ別のローテーションタイミング：**

| Squadサイズ | ローテーション間隔 |
|------------|-------------------|
| デュオ | 5分 |
|  Trio | 4分 |
|  クアトロ | 3分 |

ローテーション中、現在のライトマネージャーは次のプレイヤーに役割を渡します。ローテーションは「light passing to [プレイヤー名]」で通知されます。

## チェイス連携

Clarkチェイス中、squadはユニットとして対応する必要があります。個別の対応は孤立と死につながります。

**チェイス対応プロトコル：**

1. リアガードがアクティブ追跡を検出した瞬間に "Chase" をコールする
2. Squadがフルスプリントに切り替え、フラッシュライトをOFFにする
3. リードが2回のコーナーブレイクがある脱出ルートを選択する
4. Squadが視覚的接触を維持しながらユニットとして移動する
5. リアガードがClarkの追跡解除をモニタリングする
6. 追跡解除後、Squadが制御された撤退ペースに切り替える

プロトコルの完全な実行には15〜20秒かかります。このウィンドウ中の規律が生存を決定します。

## Squad失敗からの回復

Squadがミスをした場合、対応が即座であれば回復可能です。パニックは回復を困難にします。

**一般的な失敗と回復：**

| 失敗 | 回復アクション |
|---------|-----------------|
| バッテリー消耗 | 音声のみモードに切り替え |
| Squadメイトが分離 | 一時停止、声かけ、再集合 |
| ライトマネージャー down | 即座に役割を渡す |
| リードが混乱 | 新しいリードを指名し、分岐点で再集合 |
| 複数のチェイス | 目的ではなく脱出に集中 |
| ボイスチャットがカオス状態 | 冷静な声を指定し、他のプレイヤーをミュート |

ほとんどの失敗は、squadが早期に認識すれば回復可能です。認識には意識が必要です。

## 役割疲労の管理

持続的な役割の責任は認知的疲労を引き起こします。Squadはエラーを防ぐために役割をローテーションする必要があります。

**疲労の兆候：**

| 兆候 | アクション |
|------|--------|
| コールアウトの見落とし | 新しい役割にローテーション |
| 反応時間の遅延 | 役割時間を短縮 |
| 感情的な反応 | 役割を渡し、フォロワーになる |
| バッテリー消耗 | すでにローテーション済み、ライトマネージャーだった |
| 決定麻痺 | リード役割を渡す |

ベテランsquadは、疲労の蓄積を防ぐために3〜5分ごとにローテーションします。

## Squad結束力の構築

Squadの結束力は、同じsquadメイトとの一貫したプレイから生まれます。ランダムなパブリックロビーが結束力を達成することはめったにありません。

**結束力構築戦略：**

| 戦略 | 効果 |
|----------|--------|
| 同じsquadと定期的にプレイ | 連携の習慣を構築 |
| 失敗したランを一緒にレビュー | 連携の崩壊を特定 |
| プライベートロビーで練習 | 役割割り当てを洗練 |
| コミュニティDiscordを使用 | 互換性のあるsquadメイトを見つける |
| Squadの基準を設定 | 長期的に品質を維持 |

最高のsquadは、毎週一緒にプレイする3〜5人のプレイヤーで構成されています。連携は自動的に行われるようになります。


**Squad連携リファレンス：**

- サーバーロック前にリード、リアガード、ライトマネージャーの役割を割り当てる
- 迅速なコミュニケーションのために標準化されたコールアウト用語を使用する
- 音声の乱雑さを防ぐためにプッシュトゥトークの規律を実施する
- 高ストレス時に安定させるために冷静な声を指定する
- 認知的疲労を防ぐために役割のローテーションを実践する
- ナビゲーション中はウェッジまたはシングルファイルのフォーメーションを維持する
- チェイスやバッテリー状況のための緊急プロトコルを事前に合意する
- 継続的な改善のために失敗したランを一緒にレビューする

**コミュニケーション規律ルール：**

- 一度に1人の発言者になることで、重複するコールアウトを防ぐ
- 事実に基づく内容にすることで、感情的なパニックの広がりを避ける
- 3秒未満の簡潔なコールアウトで応答時間を維持する
- 連携が重要なときは、カオスなプレイヤーをミュートする
- より良い音声品質のために外部のDiscord音声を使用する
- 背景雑音を避けるために一貫してプッシュトゥトークを使用する


## よくある質問

**Clarkハスルームの理想的なsquadサイズは何ですか？**

3プレイヤーが理想的です。 Trioは、連携のオーバーヘッドが管理不能になることなく、役割カバレッジを提供します。

**良いsquadメイトを見つけるにはどうすればよいですか？**

コミュニティDiscordとWikiのsquad募集が最良の情報源です。同じsquadメイトとの一貫したプレイが、良好な連携への最速の道です。

**ランダムなパブリックプレイヤーとプレイできますか？**

はい、ただし連携は限定されます。パブリックロビーの連携には、ゲーム前の明示的な合意が必要ですが、ほとんどのランダムプレイヤーはそれに関与しません。

**Squadの結束力を構築するのにどれくらい時間がかかりますか？**

通常、同じsquadメイトとの5〜10セッション。20セッション後、連携は自動的に行われるようになります。

**Squadが役割について合意できない場合はどうすればよいですか？**

各プレイヤーの強みに基づいて役割を割り当ててください。音声に精通したプレイヤーはリアガードになります。空間的思考を持つプレイヤーはリードになります。規律のあるプレイヤーはライトマネージャーになります。

役割のメカニズムの詳細については、[マルチプレイヤー連携ガイド](/en/guides/multiplayer-coordination/)をご覧ください。連携を必要とする脱出戦術を学ぶには、[Clarkからの脱出](/en/guides/escaping-clark/)をお読みください。


**有害なsquadメイトにはどうすればよいですか？**

有害なプレイヤーは直ちにミュートしてください。ポジティブなsquadメイトとの連携に集中してください。Squad全体が有害な場合は、ロビーを離れてより良いプレイヤーを見つけてください。コミュニティチャネルを通じた長期的なsquad構築により、ランダムな有害行動への露出が減ります。

**Squadが戦略について意見が合わない場合はどうすればよいですか？**

ゲーム前の戦略合意により、ラン中の競合を防ぎます。プレイ中に意見の相違が生じた場合は、割り当てられたリードに従ってください。ラン後の議論で戦略の問題を建設的に解決できます。即時の失敗に直面している場合を除き、ラン中に戦略を変更しないでください。

**時間とともにsquadとしてどのように改善しますか？**

定期的な一緒にプレイすることで連携の習慣が構築されます。改善領域を特定するために失敗したランをレビューします。チェイスやバッテリー管理などの特定のシナリオを練習します。バランスの取れたsquadメンバーを育成するために役割をローテーションします。複数のセッションにわたって進捗を追跡します。

**RobloxボイスチャットとDiscordのどちらを使用すべきですか？**

Discordは、一般的にRobloxボイスチャットよりも優れた音声品質とより多くの機能を提供します。Discordはプッシュトゥトーク、ノイズ抑制、チャネル分離をサポートします。Robloxボイスは便利ですが、信頼性が低いです。ほとんどの連携squadはDiscordを好みます。

**カオスなロビーでコミュニケーションを取る最良の方法は何ですか？**

標準化されたコールアウトを使用し、延長された議論を避けてください。プッシュトゥトークの規律により音声の乱雑さを防ぎます。冷静な声の指定はコミュニケーションの安定に役立ちます。Squadに集中するためにカオスなプレイヤーをミュートします。

**異なるタイムゾーンの友人とプレイできますか？**

タイムゾーンの違いにはスケジュールの柔軟性が必要です。一部のsquadは、重複する時間にプレイすることで複数のタイムゾーンにまたがって連携しています。他のsquadは、地域のサブsquadを形成します。特定の状況に合った方法を見つけてください。

**新しいsquadメイトとの信頼をどのように構築しますか？**

信頼は、一貫したプレイと信頼性の高いパフォーマンスを通じて構築されます。スケジュールされたときに現れ、役割を果たし、明確にコミュニケーションします。ドラマを避け、ゲームプレイに集中してください。信頼は複数のセッションにわたって自然に発展します。
