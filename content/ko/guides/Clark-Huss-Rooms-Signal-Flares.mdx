Clark Huss 룸의 시그널 플레어는 길고 복잡한 음성 채팅 없이 스쿼드가 조정할 수 있도록 하는 표준화된 통신 마커입니다. 게임에는 실제 플레어 아이템이 포함되어 있지 않지만, 이 용어는 베테랑 스쿼드가 거리 통신에 사용하는 손전등 패턴, 오디오 큐, 콜아웃 어휘 시스템을 의미합니다. 신 플레이어는 음성 채팅에만 의존하는데, 이는 속도가 느리고 패닉에 빠지기 쉽습니다. 베테랑들은 시그널 플레어를 사용하여 2초 이내에 복잡한 정보를 전달합니다.

이 가이드는 시각 신호 역할을 하는 손전등 클릭 패턴, 오디오 신호 역할을 하는 표준화된 콜아웃, 스쿼드 전체의 대응을 유발하는 긴급 프로토콜을 다룹니다. 또한 스쿼드별 시그널 플레어 시스템을 구축하는 방법과 신호가 오용될 때 발생하는 가장 일반적인 실수도 배우게 됩니다.

## 시그널 플레어란 무엇인가

시그널 플레어는 긴 음성 채팅 문장을 대체하는 사전 합의된 통신 단축키입니다. 발신자와 수신자가 미리 의미를 알고 있기 때문에 해석 시간이 필요 없어 효과적입니다.

### **시그널 플레어 카테고리:**

| 카테고리 | 매체 | 범위 | 정보 밀도 |
|----------|--------|-------|---------------------|
| 손전등 패턴 | 시각 | 1 — 2개 복도 | 낮음에서 중간 |
| 오디오 콜아웃 | 음성 | 서버 전체 | 높음 |
| 행동 신호 | 움직임 | 인접 복도 | 중간 |
| 배터리 상태 | 암묵적 시각 | 서버 전체 | 낮음 |

네 가지 카테고리가 결합되어 완전한 통신 시스템을 형성합니다. 대부분의 스쿼드는 네 가지 모두를 혼합하여 사용합니다.

## 손전등 패턴 신호

손전등 패턴은 사전 합의된 의미를 전달하는 클릭 시퀀스입니다. 패턴은 짧습니다. 긴 시퀀스는 배터리와 시간을 낭비하기 때문입니다.

### **표준 손전등 패턴:**

| 패턴 | 의미 |
|---------|---------|
| 단일 클릭 | 확인, "나 당신을 보고 있다" |
| 이중 클릭 | 주의, "멈추고 평가하세요" |
| 삼중 클릭 | Clark 발견, "나를 향한 방향" |
| 빠른 클릭 (5회 이상) | 긴급, "지금 도움이 필요함" |
| 길게 누르기 | 안전한 복도 표시, "이쪽으로 오세요" |
| 껐다 켜기 | 확인 요청, "아직 살아있나?" |

이러한 패턴은 수신 스쿼드가 음성 채팅 없이 인식할 수 있기 때문에 효과적입니다. 단일 클릭은 보편적으로 확인으로 이해됩니다. 삼중 클릭은 보편적으로 Clark를 의미합니다.

## 오디오 콜아웃 신호

오디오 콜아웃은 음성이 언어를 전달하기 때문에 가장 정보 밀도가 높은 시그널 플레어입니다. 과제는 추격 중에 충분히 빠르게 콜아웃을 유지하는 것입니다.

### **표준 콜아웃 어휘:**

| 콜아웃 | 의미 |
|---------|---------|
| "Clark left" | Clark가 발언자의 왼쪽에 있음 |
| "Clark right" | Clark가 발언자의 오른쪽에 있음 |
| "Clark back" | Clark가 스쿼드 뒤에 있음 |
| "Clark front" | Clark가 스쿼드 앞에 있음 |
| "Breathing close" | Clark 오디오 단서가 한 복도 이내에 있음 |
| "Heartbeat distant" | Clark 오디오 단서가 두 개 이상의 복도 떨어진 곳에 있음 |
| "Chase" | Clark가 적극적으로 추격 중, 전력 질주 |
| "Clear" | 모니터링 영역에 Clark 오디오 단서 없음 |
| "Dead end" | 복도에 출구 없음 |
| "Door" | 잠긴 문 근처에 있음 |
| "Junction" | 의사결정 지점 접근 중 |
| "Battery" | 배터리 상태 업데이트 필요 |
| "Battery dead" | 손전등 소진 |
| "Safe corridor" | 표시된 복도가 앞에 있음, 진입 안전 |

어휘는 짧고 사실적이며 모호하지 않습니다. 어휘에서 벗어나면 혼란이 생깁니다.

## 행동 신호

행동 신호는 음성 채팅 없이 소통하는 움직임입니다. 음성 채팅을 사용할 수 없거나 스쿼드가 무음으로 소통해야 할 때 유용합니다.

### **표준 행동 신호:**

| 신호 | 움직임 |
|--------|----------|
| 스쿼드 정지 | 리더가 손을 들거나 멈춤 |
| 스쿼드 전진 | 리더가 다시 걷기 시작 |
| 스쿼드 숨기 | 모든 플레이어가 웅크리거나 정지 |
| 스쿼드 후퇴 | 모든 플레이어가 방향을 바꿈 |
| 웨지 형성 | 플레이어가 웨지 대형으로 이동 |
| 버디업 | 플레이어가 가장 가까운 스쿼드원과 짝을 맺음 |
| 조명 끄기 | 라이트 매니저가 손전등을 끔 |
| 조명 켜기 | 라이트 매니저가 손전등을 켬 |
| 따라오기 | 리더가 이동하고 스쿼드가 따름 |
| 위치 유지 | 리더가 멈추고 스쿼드도 멈춤 |

행동 신호는 스쿼드가 차분한 상황에서 연습했을 때 가장 효과적입니다. 패닉 상태에서는 스쿼드가 신호를 잊어버리고 음성 채팅으로 돌아갈 수 있습니다.

## 긴급 프로토콜

긴급 프로토콜은 특정 스쿼드 대응을 유발하는 시그널 플레어입니다. 상황이危急하기 때문에 일반 조정 규칙을 우회합니다.

**긴급 프로토콜 트리거:**

| 트리거 | 신호 | 스쿼드 대응 |
|---------|--------|----------------|
| 스쿼드원 쓰러짐 | "Man down, [방향]" | 가장 가까운 팀원이 복구하러 이동, 나머지는 엄호 |
| Clark 추격 | "Chase, full sprint" | 모든 플레이어가 전력 질주, 손전등 끄기, 리더가 탈출 경로 안내 |
| 스쿼드원 분리 | "Separation, [방향]" | 스쿼드가 일시 정지, 분리된 플레이어에게 소리침 |
| 배터리 방전 | "Battery dead, [플레이어]" | 스쿼드가 오디오 전용 모드로 전환 |
| 매복 | "Ambush, [방향]" | 스쿼드가 즉시 후퇴, 질문 없음 |
| 출구 발견 | "Exit, [방향]" | 스쿼드가 출구로 집결, 리더가 경로 확인 |

긴급 프로토콜은 즉시 필요할 수 있으므로 암기됩니다. 스쿼드는 게임 전 브리핑 중에 이를 훈련합니다.

## 배터리 상태 신호

배터리 상태는 손전등 바 가시성을 통해 암묵적으로 전달됩니다. 라이트 매니저는 음성 채팅 없이 배터리 상태를 전달하기 위해 특정 신호를 사용합니다.

**배터리 상태 신호:**

| 배터리 상태 | 신호 |
|---------------|--------|
| 70% 이상 | 정상 클릭 패턴, 표시 불필요 |
| 50 — 70% | 라이트 매니저가 매 분마다 "battery half" 호출 |
| 25 — 50% | 라이트 매니저가 단일 클릭만 사용 |
| 25% 미만 | 라이트 매니저가 "battery critical" 호출 |
| 10% 미만 | 라이트 매니저가 "battery dying" 호출 |
| 0% | 손전등 클릭이 더 이상 등록되지 않음, 오디오 전용 |

라이트 매니저의 책임은 스쿼드에게 배터리 상태를 알리는 것입니다. 스쿼드는 이 정보를 사용하여 손전등 사용을 계획합니다.

## 스쿼드 신호 시스템 구축

모든 스쿼드는 자신의 플레이스타일에 맞는 신호 시스템을 구축해야 합니다. 위의 표준 신호는 출발점이지만, 스쿼드는 종종 이를 맞춤 설정합니다.

**신호 시스템 맞춤 설정 옵션:**

1. 서버에서 흔한 상황에 대한 스쿼드별 콜아웃 추가
2. 스쿼드가 실행하기 쉬운 손전등 패턴 사용
3. 게임 버전이 플레이어 색상을 지원하는 경우 색상 역할 할당
4. 특정 이벤트를 위한 오디오 시그니처(특정 문구) 생성
5. 다가오는 결정을 위한 사전 예방적 신호 개발

맞춤 설정은 첫 번째 실행 전에 문서화되고 연습되어야 합니다. 연습 없이 맞춤 설정하면 압박 상황에서 신호를 잊어버립니다.

## 압박 상황에서의 신호纪律

압박 상황에서 신호纪律가 무너지는데, 이때 스쿼드가 신호를 가장 많이 필요로 합니다. 아래纪律 규칙은 이러한 붕괴를 방지합니다.

**纪律 규칙:**

1. 신호만 사용 — 추격 중 즉흥적인 음성 채택 금지
2. 한 번에 하나의 신호 — 동시다발적인 신호는 혼란을 야기
3. 간결한 실행 — 신호는 2초 이내에 완료되어야 함
4. 보편적 어휘 — 표준 신호에서 벗어남은 허용되지 않음
5. 침착한 실행 — 신호는 침착한 목소리로 전달되어야 함

스쿼드원이 신호纪律에서 벗어나면, 라이트 매니저는 사실적인 콜아웃으로 그들을 재정렬해야 합니다: "신호만 사용하세요."

## 일반적인 신호 실패

이러한 실패는 스쿼드가 신호를 오용할 때 일관되게 나타납니다. 이를 식별하면 예방하는 데 도움이 됩니다.

**실패 1: 즉흥적인 음성 채팅.** 스쿼드원이 추격 중에 표준 콜아웃 대신 전체 문장을 사용합니다. 문장에 5초가 걸리면 스쿼드는 5초의 대응 시간을 잃습니다.

**실패 2: 동시다발적인 신호.** 두 명의 스쿼드원이 동시에 신호를 보냅니다. 스쿼드는 어떤 신호가 우선인지 결정할 수 없으며, 대응이 지연됩니다.

**실패 3: 일관성 없는 어휘.** 스쿼드원들이 동일한 개념에 다른 단어를 사용합니다("chase" 대 "running" 대 "go go go"). 스쿼드는 어떤 단어가 올바른지 해석하는 데 시간을 낭비합니다.

**실패 4: 압박 상황에서 잊혀진 신호.** 스쿼드원들이 추격 중에 신호 어휘를 잊어버리고 감정적 반응으로 돌아갑니다. 신호는 암기가 필요하기 때문에 실패합니다.

**실패 5: 신호 스팸.** 스쿼드원이 빠르게 손전등을 클릭하거나 콜아웃을 반복하여 Clark 오디오 단서를 가리는 노이즈를 만듭니다. 신호纪律는 빈도에 대해 엄격합니다.

## 신호 실행 훈련

신호 실행은 패턴을 빠르고 정확하게 전달해야 하므로 연습이 필요합니다. 아래 훈련 운동은 근육 기억을 구축합니다.

**운동 1: 손전등 패턴 드릴.** 빈 로비에서 각 손전등 패턴을 10회씩 연습합니다. 패턴이 의식적인 생각 없이 실행되도록 근육 기억을 구축합니다.

**운동 2: 콜아웃 속도 드릴.** 각 표준 콜아웃을 전달하는 시간을 측정합니다. 목표 전달 시간은 콜아웃당 1초 미만입니다.

**운동 3: 신호 인식 드릴.** 스쿼드원이 무작위로 신호를 보내게 합니다. 1초 이내에 신호를 식별합니다. 모든 표준 신호로 반복합니다.

**운동 4: 추격 시뮬레이션.** 일반 세션을 실행하되, Clark 오디오 단서가 나타날 때마다 스쿼드가 신호 전용 통신으로 전환합니다. 이는 압박 상황에서의 신호 사용을 구축합니다.

**운동 5: 긴급 프로토콜 드릴.** 세션당 최소 한 번씩 각 긴급 프로토콜을 연습합니다. 암기에는 반복이 필요합니다.

## 솔로 플레이에서의 시그널 플레어

솔로 플레이는 스쿼드 신호의 이점을 얻지 못하지만, 솔로 플레이어는 자기 규율을 유지하기 위해 자기 신호를 사용할 수 있습니다. 자기 신호는 플레이어가 혼자 규제를 위해 실행하는 패턴입니다.

**솔로 자기 신호:**

| 신호 | 자기 규제 용도 |
|--------|---------------------|
| 모든 분기점에서 단일 클릭 | 손전등纪律 유지 |
| 발걸음 수 세기 | 제어된 페이스 유지 |
| 모든 턴에서 스테미너 확인 | 자원 인식 유지 |
| 매 분마다 배터리 확인 | 배터리 관리 유지 |

솔로 플레이어는 스쿼드의 책임감 없이도纪律를 시행하기 때문에 이러한 신호의 이점을 얻습니다.

## 자주 묻는 질문

**시그널 플레어가 임의의 공개 플레이어와 작동하나요?**

드물게 작동합니다. 임의의 플레이어는 스쿼드의 신호 시스템을 모릅니다. 시그널 플레어는 어휘를 연습한 일관된 스쿼드원에게 가장 효과적입니다.

**표준 신호 어휘를 맞춤 설정해야 하나요?**

예, 하지만 스쿼드가 표준 어휘를 마스터한 후에만 가능합니다. 맞춤 설정은 복잡성을 더하며, 표준 어휘는 대부분의 상황에서 충분합니다.

**스쿼드가 얼마나 많은 신호를 암기해야 하나요?**

표준 어휘에는 약 15개의 신호가 있습니다. 5~10개의 스쿼드별 신호를 추가하면 총 20~25개의 신호가 됩니다. 그 이상으로 가면 시스템이 압박 상황에서 기억하기에는 너무 복잡해집니다.

**가장 중요한 신호는 무엇인가요?**

"Chase" 신호는 가장 중요한 신호입니다. 왜냐하면 가장 중요한 스쿼드 대응을 유발하기 때문입니다. 모든 스쿼드원은 후위 경비원이 호출할 때 즉시 실행해야 합니다.

**시그널 플레어가 음성 채팅을 완전히 대체할 수 있나요?**

잘 연습된 스쿼드에서는 가능합니다. 신호 시스템은 모든 일반적인 시나리오를 다룹니다. 음성 채팅은 신호로 해결할 수 없는 비정상적인 상황을 위해 예약됩니다.

신호를 실행하는 스쿼드 역할에 대한 자세한 내용은 [협동 생존 가이드](/en/multiplayer/co-op-survival-guide/)를 참조하세요. 시그널 플레어가 가능하게 하는 탈출 전술을 배우려면 [Clark로부터 탈출하기](/en/guides/escaping-clark/)를 읽으세요.


**커뮤니티와 도구 및 발견을 공유하려면 어떻게 해야 하나요?**

커뮤니티 Wiki와 Discord가 도구를 공유하는 주요 채널입니다. Wiki 기여는 편집 표준을 따르지만, Discord는 더 비공식적으로 덜 구조화된 공유를 허용합니다. 대부분의 성공적인 도구는 사용 가능한 리소스의 격차를 식별한 다음 커뮤니티와 협력하여 접근 방식을 개선하는 개별 기여자에서 시작됩니다. 유용한 도구를 만들었다면, 다른 사람들이 혼동 없이 채택할 수 있도록 입출력 사양 및 사용 예시와 함께 명확하게 문서화하세요.

**의존하던 도구가 작동을 멈추면 어떻게 해야 하나요?**

도구의 문서화된 피드백 채널을 통해 즉시 문제를 보고하세요. Wiki 기반 도구의 경우 토론 페이지를 사용하세요. Discord에서 공유된 도구의 경우 작성자에게 직접 연락하세요. 대부분의 커뮤니티 도구 유지 관리자는 버그 보고에 반응적이며 사전 알림에 감사합니다. 수정 대기를 동안 대체 도구나 수동 방법으로 전환하세요. 다른 영향을 받은 사용자가 임시 솔루션의 이점을 얻을 수 있도록 워크어라운드를 문서화하세요.

**제3자 도구에 계정 정보를 신뢰할 수 있나요?**

계정 자격 증명을 어떤 도구와도 공유하지 마세요. 합법적인 도구는 게임의 공개 인터페이스를 통해 작동하며 로그인이 필요하지 않습니다. 도구가 Roblox 비밀번호를 요청한다면, 명시된 목적에 관계없이 합법적이지 않습니다. 통계 추적과 같은 개인화된 기능의 경우 도구는 비밀번호가 아닌 공개된 게임 내 사용자 이름만 요청해야 합니다.

**새 도구를 배우는 데 얼마나 걸리나요?**

대부분의 커뮤니티 도구는 직관적인 인터페이스를 가지고 있어 몇 분 내에 기본 사용이 가능합니다. 숙련은 일반적으로 도구의 복잡성에 따라 정기적인 사용으로 1 — 2주가 걸립니다. 오디오 분석기는 훈련 방법론에 여러 단계가 있기 때문에 더 많은 시간이 필요합니다. 배터리 계산기 및 패치 추적기는 더 간단하고 배우기 쉽습니다. 커뮤니티 Discord 채널에는 종종 새로운 사용자가 학습 곡단을 거치도록 도와줄 의향이 있는 베테랑 사용자가 있습니다.

**여러 도구를 동시에 사용해야 하나요?**

예, 보완적인 도구는 서로를 향상시킵니다. 예를 들어, 배터리 계산기와 함께 오디오 분석기를 사용하면 오디오 기술 개발과 자원 관리 계획이 모두 제공됩니다. 핵심은 도구가 서로 충돌하거나 정보로 압도되지 않도록 하는 것입니다. 필수 도구 하나 또는 두 개로 시작한 다음 편안해지면 더 추가하세요.

**도구의 품질을 어떻게 알 수 있나요?**

품질 지표에는 활발한 유지 관리, 커뮤니티 토론, 명확한 문서화, 정기적인 업데이트 및 긍정적인 베테랑 추천이 포함됩니다. 몇 달 동안 업데이트되지 않은 도구는 방치되었을 수 있습니다. 활발한 Discord 채널과 반응적인 유지 관리자가 있는 도구는 더 신뢰할 수 있는 경향이 있습니다. 커뮤니티 평판은 강력한 품질 지표입니다.
